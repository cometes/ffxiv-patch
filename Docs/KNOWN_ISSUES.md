# 현재 알려진 제한 사항

이 문서는 현재 동작에 영향을 주는 제한과 회귀 방지 규칙만 기록한다. 과거 실험 산출물, 폐기된 구현의 상세 이력, 세션별 작업 로그는 포함하지 않는다.

## 사용자 보고로 확인된 마수조련사 문제

사용자 제보와 v7.56 데이터 점검으로 파악한 항목이다. 번역 경로와 발바닥 복원 코드는 수정하고 합성 입력으로 검증했다. 제목·랭크업 배치는 원본 ULD가 없어 미수정이며, 실제 게임 화면에서 해결됐다고 판단하지 않는다.

### 마수조련사 번역 누락 — 코드 수정

- `一流魔獣使い`는 `XBMScoreRank` 행 4의 문자열이다. 한국어 v7.56 원문은 `일류 마수조련사`다.
- v7.56의 XBM 시트 20개 중 직접 문자열을 가진 시트는 8개다. 현재 이 8개를 명시적 행 번호 번역 경로로 처리한다.
- 이전에 빠졌던 `XBMActionEffectType`, `XBMActionTarget`, `XBMElement`, `XBMScoreRank`의 정확한 이름을 추가했다. 이 시트들은 문자열 필드가 하나뿐이라 두 문자열 열을 요구하는 문자열 키 경로로는 처리되지 않았다.
- JA/EN 기반 합성 실행에서 새 경로의 한국어 치환, 기존 네 경로, Remainder=Base, 빈 값·누락 원본·미존재 페이지 보존, 한국어 전용 행 제외, GUI 제어 바이트 보존을 확인했다. `XBM*` 전체 허용으로 확대하지 않았다.

### 빈 한국어 부제의 원문 보존

- 한국어가 빈 `Addon#17701` 등의 부제를 기본 언어 원문으로 남기는 것은 사용자 요구에 따른 의도된 동작이며 번역 버그가 아니다.
- 이번 수정에서 부제 숨김 정책이나 강제 빈 문자열 remap을 추가하지 않는다. 일반적인 빈 값·누락 원본 보존을 유지한다.
- 마수도감 제목 배치를 수정할 때도 보존된 원문 부제를 삭제하거나 가리지 않는다.

### 한국어 원자료에 남은 외국어

- `Addon#17614`, `17662`, `17694`, `17695`는 한국어 원자료 자체에 일본어 또는 영어가 남아 있다. 내부 준비 문구와 확인 매크로 등이 포함되며 실제 사용 여부는 미확정이다. 생성기 경로 누락과 구분해 원자료 보완·표시 여부 확인 대상으로 둔다.
- Addon 298행 및 연결된 UI 원자료를 점검했다. 기술 설명 143행 중 134행은 한국어이며 나머지 9행은 JA/EN에서도 빈 값이다. 관련 상태 18행의 이름·설명 36개와 구체적으로 연결된 시련 적 이름도 한국어 원자료를 확인했다. 이 점검을 실제 생성 EXD·동적 분기·클라이언트 전체의 무누락 보장으로 해석하지 않는다.

### 마수도감 제목의 창 경계 어긋남

- 제목 문구는 `Addon#17700`으로 추적했다. 현재 생성기에는 마수도감 전용 ULD 좌표·폭 보정이 없다.
- 제공된 화면에서는 큰 제목이 상단 장식 프레임에 닿거나 가려진다. 공식 한국어 화면은 작은 제목과 부제 없는 구성을 사용한다.
- 실제 글로벌·한국어 ULD의 해당 노드 폰트·크기·정렬·경계를 먼저 비교한다. 노드 설정이 같다면 생성된 FDT의 베이스라인·전진 폭·가시 영역을 비교한다. UI 배율과 원본 노드가 없는 상태에서 임의 좌표 이동이나 공용 폰트 축소를 적용하지 않는다.

### 마수 랭크업 문구 잘림

- 결과창의 랭크업 문구는 `Addon#17888`이다. 인접한 랭크/발바닥 문자열 `Addon#17889`와 분리해 조사한다.
- 제공된 화면에서는 마수 카드마다 오른쪽 끝 잘림이 반복된다. 카드 간격 대비 금색 글자 높이는 공식 한국어 예시보다 약 1.5배 크다. 이는 상대적인 화면 점유율이며, 실제 폰트 크기나 보정 배율을 뜻하지 않는다.
- 공통 카드 라벨 노드의 폰트 설정과 가로 폭·베이스라인·클립 경계를 확인한다. 개별 마수 10개를 따로 고치거나 창 전체를 확대하지 않는다.
- 두 배치 문제는 별도 글로벌·한국어 backup/export의 버전이 맞는 ULD와 참조 폰트, 사용 중인 UI 배율이 필요하다. 현재 자료 없이 노드 좌표나 글자 크기를 추측해 변경하지 않았다.

### 마수 랭크 발바닥이 등호로 표시됨 — 복원 코드 수정

- `Addon#17889`의 발바닥은 `U+E036`이다. 조사한 배포 TTMP의 비로비 FDT 27개에는 모두 이 글리프가 없었다. 출력 FDT와의 교집합만 보는 방식으로는 이 누락을 필수 복원 대상으로 잡지 못했다.
- 이제 대응하는 clean 글로벌 FDT에 E036이 있는 비로비 경로에만 같은 코드포인트의 글리프와 atlas/mip를 복원한다. KrnAXIS의 기존 AXIS 대응을 재사용하며, 다른 PUA의 폰트 범위는 넓히지 않았다.
- 기존 글리프 할당을 모두 마친 뒤 발바닥을 별도 할당하고 원본 mip 정렬을 유지한다. 빈 원본, 할당 실패, 필요한 텍스처 미출력은 생성 실패로 처리한다.
- 기본 `beastmaster-paw` 검사는 원본으로 증명되는 경로의 누락·빈 형태·등호 폴백·base/mip 불일치를 검사한다. 비교용 `=`나 검증 가능한 발바닥 경로가 없다는 이유로 잘못 통과시키지 않는다.
- 합성 AXIS_12/KrnAXIS_120/MiedingerMid_18 복원, 비정렬 원본 좌표, 기존 기호·숫자·영문·한글·다른 PUA의 네 mip 단계 보존을 확인했다. 실제 백업 전체와 게임 UI 배율별 검증은 아직 수행하지 않았다.

## 실기 확인 대기

### 선택 구성과 마수 조련사 텍스트

- WPF 선택·저장·확인·제거 흐름과 합성 EXD/ULD/SqPack 입력을 이용한 생성·복구·재추출을 검증했다.
- 별도 백업에서 내보낸 실제 한국어/글로벌 데이터로 전체 폰트 포함 패치를 생성하고, 실제 게임에서 JA/EN 스토리·마수 조련사 문자열 및 화면을 확인하는 단계는 아직 수행하지 않았다.
- 합성 데이터의 PASS를 실제 클라이언트 호환성이나 무충돌 보장으로 해석하지 않는다.

### 케프카 전투 시작 상용구

- `InstanceContentTextData#45500`의 한국어 RSV 본문과 `Icon(54/55)` 매크로 바이트 생성은 검증됐다.
- 실제 전투 대화창에서 한국어 본문과 상용구 외형이 함께 표시되는지는 사용자 확인 전까지 미확인이다.

### UI 배율별 큰 한글 라벨

- 비로비 `TrumpGothic_23/34/68.fdt`의 한글 시각 크기 보정은 생성 산출물 검증을 통과했다.
- ActionDetail, PvP 프로필 등 실제 100%/150%/200%/300% 화면의 상대 크기는 사용자 확인이 필요하다.

### 저배율 파티 번호 마커

- 120% 이하에서 파티 목록·채팅 번호 마커 주변 픽셀이 오염될 가능성이 남아 있다.
- `U+E031`, `U+E037`, `U+E0B1`~`U+E0B8`, `U+E0E1`~`U+E0E8`의 glyph와 base/mip texture 주변을 clean 기준으로 보호해야 한다.

## 기능 제한

- `ExcelVariant.Subrows` 시트는 지원하지 않으며 진단 파일에 `unsupported-subrows`로 기록한다.
- 퀘스트 Say 문구 익명화는 커버리지가 불완전해 비활성화되어 있다. CLI 옵션은 경고만 출력하는 no-op이다.
- 글로벌·한국 클라이언트 버전이 다르거나 clean/original index를 확보할 수 없으면 실제 패치 생성을 중단한다.
- 실제 설치 폴더는 clean 기준선으로 사용하지 않는다. 별도 백업의 restore baseline 또는 산출물의 `orig.*` index를 사용한다.

## 폰트 회귀 방지 규칙

- `font-only` 범위는 [FONT_ONLY_PATCH_SCOPE.md](FONT_ONLY_PATCH_SCOPE.md)를 따른다.
- shared atlas를 수정할 때 `Jupiter_45/90` damage-number route와 `font3.tex`의 기존 한글 영역을 오염시키지 않는다.
- 로비 폰트 변경 전에는 [LOBBY_FONT_REWORK_PLAN.md](LOBBY_FONT_REWORK_PLAN.md), [LOBBY_ROUTE_SURVEY.md](LOBBY_ROUTE_SURVEY.md), [HD_FHD_LOBBY_PAGE_BUDGET.md](HD_FHD_LOBBY_PAGE_BUDGET.md)를 확인한다.
- 생성 결과가 보인다는 사실만으로 완료 처리하지 않는다. 관련 verifier와 실제 화면 확인을 구분한다.
